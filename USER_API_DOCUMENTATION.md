# User Management API Documentation

## Database Schema Reference

The User Management APIs interact with the following table from the Terrain database:

```sql
CREATE TABLE Users (
  user_id INT AUTO_INCREMENT PRIMARY KEY,
  username VARCHAR(50) NOT NULL UNIQUE,
  email VARCHAR(100) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

## API Endpoints

### 1. Create User
**POST** `/api/users`

Creates a new user account.

**Request Body:**
```json
{
  "username": "john_doe",
  "email": "john@example.com",
  "password_hash": "hashed_password_here"
}
```

**Response (201 Created):**
```json
{
  "success": true,
  "message": "User created successfully",
  "user": {
    "user_id": 1,
    "username": "john_doe",
    "email": "john@example.com"
  }
}
```

**Error Responses:**
- `400 Bad Request`: Missing required fields (username, email, password_hash)
- `409 Conflict`: Email or username already exists
- `500 Server Error`: Database error

**Example cURL:**
```bash
curl -X POST http://localhost:3001/api/users \
  -H "Content-Type: application/json" \
  -d '{
    "username": "john_doe",
    "email": "john@example.com",
    "password_hash": "hashed_password_here"
  }'
```

---

### 2. Get User by ID
**GET** `/api/users/:userId`

Retrieves user information by user ID.

**Example:** `/api/users/1`

**Response (200 OK):**
```json
{
  "success": true,
  "user": {
    "user_id": 1,
    "username": "john_doe",
    "email": "john@example.com",
    "created_at": "2025-12-03 10:30:50",
    "updated_at": "2025-12-03 10:30:50"
  }
}
```

**Error Responses:**
- `404 Not Found`: User not found
- `500 Server Error`: Database error

**Example cURL:**
```bash
curl http://localhost:3001/api/users/1
```

---

### 3. Get User by Email
**GET** `/api/users/email/:email`

Retrieves user information by email address.

**Example:** `/api/users/email/john@example.com`

**Response (200 OK):**

```json
{

    "user_id": 1,
    "username": "john_doe",
    "email": "john@example.com",
    "created_at": "2025-12-03 10:30:50",
    "updated_at": "2025-12-03 10:30:50"
  }
}
```

**Error Responses:**
- `404 Not Found`: User not found
- `500 Server Error`: Database error

**Example cURL:**
```bash
curl http://localhost:3001/api/users/email/john@example.com
```

---

### 4. Update User Profile
**PUT** `/api/users/:userId`

Updates user profile information (username and/or email).

**Example:** `/api/users/1`

**Request Body (at least one field required):**
```json
{
  "username": "jane_doe",
  "email": "jane@example.com"
}
```

**Response (200 OK):**
```json
{
  "success": true,
  "message": "User updated successfully",
  "user": {
    "user_id": 1,
    "username": "jane_doe",
    "email": "jane@example.com"
  }
}
```

**Error Responses:**
- `400 Bad Request`: No fields to update
- `404 Not Found`: User not found
- `409 Conflict`: Username or email already in use by another user
- `500 Server Error`: Database error

**Example cURL:**
```bash
curl -X PUT http://localhost:3001/api/users/1 \
  -H "Content-Type: application/json" \
  -d '{
    "username": "jane_doe",
    "email": "jane@example.com"
  }'
```

---

### 5. Delete User
**DELETE** `/api/users/:userId`

Permanently deletes a user account.

**Example:** `/api/users/1`

**Response (200 OK):**
```json
{
  "success": true,
  "message": "User deleted successfully",
  "deletedUserId": 1
}
```

**Error Responses:**
- `404 Not Found`: User not found
- `500 Server Error`: Database error

**Example cURL:**
```bash
curl -X DELETE http://localhost:3001/api/users/1
```

## User ID Storage

- **user_id** is automatically generated by the database (AUTO_INCREMENT)
- Returned in the response when a user is created
- Used as the primary identifier for all future API requests
- Should be stored in the frontend (localStorage, context, etc.) for authenticated sessions

## Security Considerations

1. **Password Hashing**: The frontend should hash passwords before sending them
2. **Email Validation**: Consider adding email validation on the frontend
3. **Username Validation**: Should follow your application's username rules
4. **Authentication**: In production, implement JWT tokens or session management
5. **HTTPS**: Always use HTTPS in production
6. **Rate Limiting**: Consider adding rate limiting to prevent brute force attacks

## Frontend Integration

When implementing on the frontend, you should:

1. Store the `user_id` after creation in localStorage or a state management solution
2. Use the `user_id` for subsequent API requests that require user context
3. Include the `user_id` as a parameter when making requests related to that user
4. Implement proper error handling for all possible error responses

Example frontend flow:
```javascript
// 1. Create user
POST /api/users → get user_id
// 2. Store user_id
localStorage.setItem('user_id', response.user.user_id)
// 3. Use user_id for other operations
GET /api/users/{user_id}
PUT /api/users/{user_id}
DELETE /api/users/{user_id}
```
